# Перенос старых названий своих препаратов

Новые записи хранят личное название в `personal_medications`, а в `medications.name` — «Свой препарат». Старые записи и уже созданные `risk_training_input_snapshots` могут содержать введённое название; для них предназначен `migrate-personal-medications.js`.

Перед применением сделайте и проверьте резервную копию рабочей MongoDB. Запускайте скрипт через `mongosh` с URI пользователя, которому разрешена запись в базу приложения. Имя базы в `CALM_PERSONAL_MEDICATION_MIGRATION_DB` должно совпадать с подключённой базой.

Сначала сухой прогон без изменений:

```sh
CALM_PERSONAL_MEDICATION_MIGRATION_DB=calm mongosh "$APP_MONGO_URI" --quiet --file backend/scripts/migrate-personal-medications.js
```

После проверки числа затронутых документов:

```sh
CALM_PERSONAL_MEDICATION_MIGRATION_DB=calm CALM_PERSONAL_MEDICATION_MIGRATION_APPLY=YES mongosh "$APP_MONGO_URI" --quiet --file backend/scripts/migrate-personal-medications.js
```

Запускайте применяющий прогон в окне обновления перед новым backend: старый backend не умеет показывать личные названия по ссылке. Скрипт создаёт уникальный индекс личного списка, сохраняет названия по владельцам, заменяет их в старых записях приёма и в исторических преддневных снимках. Повторный запуск не создаёт дубликаты. Снимки используют названия только из общего справочника; остальные названия заменяются на «Свой препарат». После миграции пересоберите обучающую выгрузку схемы 3: новый цикл удаляет предыдущие поколения строк. Уже созданные внешние копии и архивные резервные копии миграция не переписывает.

Если старый снимок содержит название, которое пользователь применял и как своё, и из общего справочника, происхождение агрегированной записи уже нельзя восстановить. В таком случае миграция и экспорт выбирают «Свой препарат», чтобы не раскрыть личное название.
