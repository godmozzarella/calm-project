# Изолированный набор общей модели риска

`export-shared-risk-training.js` строит полную актуальную выборку из базы `calm` в отдельную базу назначения `calm_risk_training`. Скрипт только читает персональную базу. Укажите для назначения отдельный Mongo URI с учётной записью, имеющей запись только в `calm_risk_training`; в рабочем пилоте предпочтителен отдельный экземпляр MongoDB. Скрипт сверяет версию и SHA-256 отпечаток из окружения с `risk_model_consent_policy.current`, которую backend публикует при запуске, и останавливается при несовпадении. Он выгружает только активные записи согласия с этой парой.

## Что попадает в обучающий набор

- Один последний прогноз на участника и целевую дату, выданный до местного начала этого дня.
- Только завершившиеся дни с подтверждённым исходом: начало приступа из записи приступа либо явная отметка «новый приступ не начинался». Неотмеченные дни пропускаются.
- Версия схемы и правил, базовый балл и только числовые признаки прогноза: погода, агрегаты приступов/приёма препаратов и объём истории.
- HMAC-SHA-256 псевдоним участника. Mongo `_id`, `userId`, email, имя, текстовые заметки, симптомы, подробности приступов и названия лекарств не выгружаются. Псевдонимизация снижает прямую связь, но не гарантирует анонимность: дата и редкие комбинации признаков всё ещё могут выделять человека.

Прогнозы со снимком признаков версии 1 и прогнозы после начала целевого дня исключаются из новой выгрузки: версия 2 добавляет число дней начала приступов за 14/30 дней, среднюю интенсивность начавшихся приступов за 30 дней и дни с последнего начала за доступные 90 дней. Средняя интенсивность приступов не равна ежедневной силе боли из исследования Nerivio. При отсутствии данных средняя и давность остаются пустыми. Старые дни без явной отрицательной отметки не считаются днями без приступа. Повторные прогнозы для одного дня сворачиваются к последнему допустимому прогнозу, поэтому активность в приложении не увеличивает вес участника.

## Пересборка

Перед каждым обучением пересобирайте набор после обработки новых отметок и отзывов. Скрипт публикует новое поколение в `calm_risk_training`, переключает `export_metadata.active` только после записи и проверки всех строк, затем удаляет старые строки, офлайн-кандидаты и результаты оценки предыдущих поколений. Для обучения читайте только документы с `generation`, указанным в `export_metadata` с `_id: "active"`. Не используйте копии базы или файлов старых поколений после отзыва участника.

Скрипт требует явно передать:

- `CALM_TRAINING_HMAC_KEY`: случайный секрет не короче 32 байт. Храните его вне репозитория и не меняйте между пересборками, иначе псевдонимы участников изменятся.
- `CALM_RISK_CONSENT_VERSION` и `CALM_RISK_CONSENT_DIGEST`: утверждённые значения из API участия. Экспорт берёт только записи с совпадающими версией и SHA-256 отпечатком текста. Оценка повторно сверяет эту пару с текущими активными согласиями.
- Для backend открытия набора нужны `CALM_RISK_PILOT_APPROVED_CONSENT_VERSION` и `CALM_RISK_PILOT_APPROVED_CONSENT_DIGEST`; укажите их только после утверждения текста. Совпадение только номера версии недостаточно.

Backend Compose читает эти настройки из `backend/.env`. Для них используйте значения `currentConsentVersion` и `currentConsentDigest`, возвращённые авторизованным `GET /api/risk/participation`; тот же номер и отпечаток задаются как `CALM_RISK_CONSENT_VERSION` и `CALM_RISK_CONSENT_DIGEST` в `backend/.env.training-worker`. Сначала текст должен быть утверждён и опубликован, затем согласованные значения копируются в оба файла. Пока этого нет, оставьте `CALM_RISK_PILOT_ENROLLMENT_OPEN=false` и не запускайте worker.

Backend при запуске записывает текущую пару в `risk_model_consent_policy` исходной базы. Экспортёр и оценщик сверяют свои настройки с этой записью до обработки обучающих строк. Поэтому после смены backend политики worker со старым env остановится, пока оператор не обновит конфигурацию; один только отдельный env-файл не может продолжить выгрузку старых согласий.
- `CALM_TRAINING_MONGO_URI`: URI отдельной базы назначения, заканчивающийся на `/calm_risk_training`.
- `CALM_TRAINING_REBUILD_CONFIRM=YES`: подтверждение замены активного обучающего набора.

Разовый запуск через Compose после настройки авторизации и переменных окружения в защищённой оболочке:

```sh
docker compose exec -T \
  -e CALM_TRAINING_MONGO_URI \
  -e CALM_TRAINING_HMAC_KEY \
  -e CALM_RISK_CONSENT_VERSION \
  -e CALM_RISK_CONSENT_DIGEST \
  -e CALM_TRAINING_REBUILD_CONFIRM=YES \
  mongo mongosh --quiet "$CALM_TRAINING_SOURCE_URI" --file /dev/stdin \
  < backend/scripts/export-shared-risk-training.js
```

`CALM_TRAINING_SOURCE_URI` должен указывать на `calm` с правом только чтения, а `CALM_TRAINING_MONGO_URI` — на отдельную обучающую базу с правом записи. После начала пилота используйте наблюдаемый worker вместо надежды на разовые ручные команды.

Не запускайте экспорт на рабочем сервере до утверждения цели, политики и окончательного текста согласия. Перед внешним пилотом отдельно проверьте права доступа к `calm_risk_training`, резервные копии и порядок физического удаления выгруженных строк и уже обученных моделей после отзыва.

Локальные проверки логики экспорта, без подключения к Mongo и без чтения пользовательских данных:

```sh
node --check backend/scripts/export-shared-risk-training.js
node --test backend/scripts/export-shared-risk-training.test.mjs
```

## Изолированная проверка прав MongoDB

```sh
bash backend/scripts/run-shared-risk-auth-test.sh
```

Сценарий поднимает отдельный временный MongoDB с авторизацией, без опубликованного порта и с данными в `tmpfs`, создаёт только синтетических участников и две ограниченные учётные записи. Он проверяет запрет записи в исходную базу и чтения чужой базы, выгрузку 300 дней, офлайн-оценку и пересборку до 290 дней после отзыва с удалением старых артефактов. Также он создаёт `mongodump` в `tmpfs`, восстанавливает его в другую тестовую базу и сравнивает пять коллекций целиком, включая BSON-значения и текущую политику согласия. После работы контейнер удаляется. Пароли в тестовых файлах фиксированные и пригодны только для этой одноразовой базы.

Эта проверка подтверждает права в отдельном тестовом окружении. Рабочая MongoDB пока не настроена на аутентификацию и не должна быть доступна по сети извне хоста; при использовании Compose её порт привязан к `127.0.0.1`. Перед внешним пилотом нужны отдельные рабочие учётные записи с минимальными правами и проверка резервного копирования и восстановления.

### Восстановление после резервной копии

Старый бэкап может содержать согласие участника, который отозвал его уже после создания копии. До открытия восстановленного приложения для пользователей сбросьте все восстановленные статусы участия до повторного согласия и очистите старый обучающий набор вместе с офлайн-моделями. Для этого есть два отдельных скрипта: `reset-shared-model-consent-after-restore.js` для исходной БД и `purge-shared-risk-training-after-restore.js` для обучающей. Каждый проверяет имя базы и требует `CALM_RISK_RESTORE_RESET_CONFIRM=YES`; на рабочей базе они не запускаются тестовым флагом. Тестовый прогон проверяет, что после такого восстановления активных согласий и прежних обучающих артефактов нет.

Операция намеренно требует нового согласия от всех участников. Она не удаляет внешние файлы, другие копии баз или модели вне `calm_risk_training`: такие артефакты нужно учитывать отдельно. Тестовый `mongodump` хранится только в `tmpfs` и доказывает механику восстановления, а не долговечность, шифрование или регламент хранения рабочих резервных копий.

## Offline-проверка кандидата модели

`evaluate-shared-risk-model.js` читает только опубликованное поколение в `calm_risk_training`. Участники целиком и детерминированно делятся между обучением и контрольной выборкой; ни один участник не попадает в обе части. Каждая запись получает вес, обратный числу дней этого участника, чтобы люди с более длинным дневником не доминировали.

Скрипт применяет предварительные технические минимумы: 3 участника, 100 размеченных дней, по 20 дней каждого исхода, не менее 1 участника в контроле, по 5 примеров каждого исхода в контроле и по 10 каждого исхода в обучении. При трёх участниках один целиком отводится в контроль, двое остаются для обучения. Это минимальный экспериментальный порог для малого пилота, а не научно обоснованный размер выборки; он **не доказывает научную или медицинскую пригодность**. Логистическая регрессия сохраняется только как offline-кандидат; действующий прогноз не меняется и автоматического включения нет. Сравниваются ROC-AUC текущего балла как ранжирования, Brier score модели и базовой частоты, а также чувствительность/специфичность при пороге 0.5 и текущем пороге 35 баллов. `candidateWorthHumanReview` — лишь повод для дальнейшей проверки, не критерий выпуска.

Перед каждой проверкой сначала выполните полную выгрузку, чтобы применились свежие согласия и отзывы. Запуск проверки против отдельной базы:

```sh
mongosh "$CALM_TRAINING_MONGO_URI" --file backend/scripts/evaluate-shared-risk-model.js
```

Проверка требует `CALM_TRAINING_SOURCE_URI` с правом только чтения исходной базы, тот же `CALM_TRAINING_HMAC_KEY`, что использует экспорт, и ту же версию/отпечаток согласия. Она откажется обучать кандидата, если снимок старше 15 минут, его policy metadata устарели или в нём есть участник, чьё текущее согласие изменилось/отозвано либо чей аккаунт удалён. URI и значения политики должны быть в окружении процесса до запуска команды выше.

### Автоматическая пересборка для пилота

Опциональный `docker-compose.training-worker.yml` запускает отдельный контейнер MongoDB Shell. Он каждые 5 минут читает исходную базу под `calm_risk_export_reader`, пересобирает обучающую базу под `calm_risk_training_writer` и удаляет предыдущие поколения и офлайн-модели. Контейнер не имеет сетевого порта; health check показывает, когда последний успешный экспорт устарел. При ошибке процесс завершается и Compose повторно его запускает.

Этот сервис **не входит** в обычный `docker compose up`. Включать его только после утверждения политики/текста согласия, настройки авторизации MongoDB и создания файла `backend/.env.training-worker` с правами владельца `600`. Файл игнорируется Git и должен содержать URI источника и назначения, стабильный HMAC-ключ, а также утверждённые `CALM_RISK_CONSENT_VERSION` и `CALM_RISK_CONSENT_DIGEST`. Проверка на отдельном тестовом томе подтвердила автоматическое появление строки после регистрации участника и её исчезновение после `DELETE /users/me`, без ручного экспорта.

После каждого успешного экспорта worker также атомарно обновляет CSV-снимок `backend/generated/risk-training/shared-risk-training.csv` на хосте через bind mount. В файле только активное поколение, HMAC-псевдоним участника, дата прогноза, подтверждённый исход и разрешённые признаки; имена, email и внутренние ID аккаунтов не выгружаются. Файл создаётся с правами `600` и исключён из Git. Он содержит чувствительные данные о здоровье, поэтому хранится только на сервере; при ошибке CSV-выгрузки worker продолжает работать с MongoDB-снимком, а предыдущий CSV сохраняется.

**Локальная проверка 2026-10-12:** по просьбе владельца локальный enrollment открыт с текущим черновым текстом и включён worker, чтобы проверить полный путь. Локальная MongoDB переведена на `--auth` с отдельными ролями; worker экспортирует каждые 5 минут в ту же локальную MongoDB, но в отдельную базу. На первом запуске было 0 активных согласий и 0 пригодных строк. Worker не обучает и не активирует модель. Этот локальный режим не разрешает внешний набор: для сервера нужны окончательное согласие и отдельное защищённое резервное копирование с восстановлением.

Текущий локальный контур с доступом к сайту по Wi-Fi/LAN запускается так:

```sh
docker compose -f docker-compose.yml -f docker-compose.auth.yml -f docker-compose.training-worker.yml -f docker-compose.lan.yml up -d
```

LAN overlay публикует frontend на localhost и на адресе Mac из `CALM_LAN_IP` в корневом игнорируемом `.env` (сейчас `192.168.31.71`). На другом устройстве той же Wi-Fi/LAN сети откройте `http://<CALM_LAN_IP>/`. Если роутер сменит IP, обновите переменную и повторите запуск Compose. Backend и MongoDB остаются привязаны к localhost, а worker не имеет опубликованного порта. HTTP подходит только для доверенной локальной сети; это не публикация в интернете и не HTTPS.

Периодическая пересборка задаёт ожидаемую задержку удаления, но не гарантирует жёсткий срок при сбое MongoDB или контейнера. Следите за health и временем `export_metadata.active.generatedAt`; при сбое остановите использование обучающего набора и устраните причину. Офлайн-оценка уже отказывает старым снимкам. Для обещания срока в условиях участия нужны мониторинг и порядок обработки аварий.

Результаты сохраняются в `risk_model_evaluations`, веса — в `risk_model_candidates` со статусом `OFFLINE_ONLY_NEVER_AUTO_ACTIVATE`. Сценарий проверки без подключения к Mongo:

```sh
node --check backend/scripts/evaluate-shared-risk-model.js
node --test backend/scripts/evaluate-shared-risk-model.test.mjs
```
