## О проекте

Calm помогает сохранять детали, которые трудно восстановить по памяти: когда началась боль, где болело, какие симптомы сопровождали приступ и насколько помог препарат. История остаётся в одном месте — её можно просматривать по дням, анализировать за период и выгружать для обсуждения с врачом.

Первая версия уже доступна в браузере на компьютере и телефоне. Сейчас использование Calm полностью бесплатное. На телефоне сайт можно добавить на главный экран; для сохранения и загрузки записей требуется подключение к интернету.

Проект развивает Кирилл Пустовойт, студент 4-го курса Воронежского государственного технического университета, направление «Информационные системы и технологии». Calm вырос из учебного проекта и развивается как самостоятельное приложение и исследование вероятности приступов головной боли.

## Возможности

| Раздел | Что можно делать |
| --- | --- |
| **Дневник приступов** | Сохранять начало и окончание приступа, интенсивность, тип боли, симптомы, возможные триггеры и заметки. Отмечать продолжающиеся приступы и добавлять записи за прошлые даты. |
| **Зоны боли** | Выбирать участки на карте головы и отмечать выраженность боли в каждой зоне с привязкой к приступу. |
| **Препараты** | Выбирать препараты из справочника или добавлять личные, указывать дозу и время приёма, связывать с приступами и оценивать эффект. |
| **Календарь** | Просматривать историю по дням, отмечать дни без новых начал приступов и видеть серию таких дней. |
| **Статистика** | Смотреть частоту и интенсивность приступов, отмеченные симптомы и триггеры, приём и пользовательские оценки эффективности препаратов. |
| **Экспорт** | Скачивать PDF-отчёт, отдельные CSV с приступами и препаратами, печатать статистику. |
| **Погода и факторы риска** | Выбирать город вручную или через геолокацию, смотреть погодные показатели и объяснение текущей оценки риска. |
| **Аккаунт** | Подтверждать почту при регистрации, восстанавливать доступ, менять пароль и почту с подтверждением, удалять аккаунт. |
| **Интерфейс** | Использовать приложение на телефоне и компьютере, выбирать светлую, тёмную или автоматическую тему. |

Для администратора предусмотрены управление пользователями и справочниками, а также email-рассылка пользователям, разрешившим уведомления. Отправка требует отдельного подтверждения.

## Исследование прогнозирования

Цель исследования — создать модель, которая будет заранее оценивать вероятность приступа на основе накопленной истории и внешних факторов. Обученная на пользовательских данных модель пока не внедрена. Доступная сейчас оценка риска рассчитывается по правилам с учётом погоды и истории; её балл не является подтверждённой вероятностью приступа в процентах.

Участие в сборе исследовательских данных добровольное и требует отдельного согласия. Дневником можно пользоваться без участия в исследовании.

Для исследования реализован отдельный экспортёр:

- собирает разрешённую историю, включая старые приступы, симптомы, зоны и связанные препараты, даже без снимка прогноза за дату;
- сохраняет пропуски, если часть параметров отсутствует;
- фиксирует место события и при возможности дополняет данные архивной погодой;
- различает сведения, сохранённые до начала дня, и данные, восстановленные задним числом;
- использует псевдонимы участников и исключает email, никнеймы, свободные заметки и точные координаты из общего набора.

Такая выгрузка предназначена для дальнейшей предобработки и исследования. Показатели завершившегося приступа и ретроспективную погоду нельзя считать признаками, которые были известны заранее. Псевдонимизация не означает полной анонимности данных.

Подробнее: [формат датасета](docs/training-data-contract.md), [местоположения и архивная погода](docs/location-history-and-weather-backfill.md), [работа training-worker](docs/server-training-integration.md).

## Начать пользоваться

1. Откройте [Calm](https://peaceofmindforyourhead.duckdns.org/), зарегистрируйтесь и подтвердите почту кодом из письма.
2. Укажите город для погодных данных. Ручной выбор сохраняется до вашего изменения; автоматический режим предлагает подтвердить обнаруженный переезд.
3. Добавьте первый приступ или отметьте день без приступов. Заполнять все необязательные поля сразу не нужно.
4. По мере накопления записей просматривайте календарь, статистику и оценки препаратов. При необходимости скачайте отчёт.

На телефоне используйте кнопку **«Установить приложение»** в футере: Calm покажет доступный способ установки или памятку для браузера.

Calm помогает вести наблюдения и подготовить записи для консультации. Приложение не ставит диагноз и не назначает лечение.

## Запуск локально

Для запуска из исходников нужен Docker с Compose. Для разработки вне контейнеров — Java 21, Maven 3.9+, Node.js 22.12+ и MongoDB 7.

```bash
git clone https://github.com/godmozzarella/calm-project.git
cd calm-project
cp backend/.env.example backend/.env
```

Заполните `backend/.env`:

- `CALM_JWT_SECRET` — случайный секрет не короче 32 байт; сгенерировать можно командой `openssl rand -base64 48`.
- Почтовый провайдер: `CALM_MAIL_PROVIDER=smtp` и параметры SMTP либо `CALM_MAIL_PROVIDER=resend` и API-ключ. Для регистрации необходима работающая отправка кода на адрес пользователя.
- `CALM_MAIL_FROM` и `CALM_PUBLIC_URL` — адрес отправителя и URL локального приложения; для запуска ниже URL — `http://localhost`.

Полный шаблон настроек: [backend/.env.example](backend/.env.example). Секреты и реальные пользовательские данные не добавляются в Git.

```bash
docker compose up -d --build mongo backend frontend
```

| Адрес | Назначение |
| --- | --- |
| `http://localhost` | Приложение |
| `http://localhost:8080/api` | REST API |
| `http://localhost:8080/api/actuator/health` | Проверка состояния backend |

MongoDB хранит данные в томе `mongo_data`, аватары — в `avatars_data`. Для обычного обновления используйте пересборку сервисов, сохраняя тома.

### Разработка с Vite

После настройки `backend/.env` запустите базу и API:

```bash
docker compose up -d --build mongo backend
```

Затем в отдельном терминале:

```bash
cd frontend
npm ci
npm run dev
```

Интерфейс откроется на `http://localhost:5173`; Vite перенаправляет `/api` на backend на порту 8080.

Для запуска backend без Docker поднимите локальную MongoDB, передайте переменные из шаблона в окружение процесса через IDE или терминал и выполните `mvn spring-boot:run` из `backend`. Maven сам по себе не загружает `backend/.env`; подключение к MongoDB по умолчанию — `mongodb://localhost:27017/calm`.

## Устройство проекта

| Часть | Технологии и назначение |
| --- | --- |
| `frontend/` | React 19, Vite, React Router, SCSS Modules, MUI Icons; адаптивный интерфейс и экспорт отчётов. |
| `backend/` | Java 21, Spring Boot 3.5, Spring Security, Spring Data MongoDB; REST API, аккаунты, дневник и аналитика. |
| `backend/scripts/` | Экспорт исследовательского набора, аудит данных, миграции и проверки. |
| `docs/` | Контракты данных, инструкции и материалы по развитию проекта. |
| `.github/` | CI и ручной выпуск на VPS по SSH. |
| `docker-compose*.yml` | Локальное окружение и отдельные конфигурации production и training-worker. |

MongoDB Community работает в контейнере. Production использует nginx для frontend и Caddy для HTTPS. Источник погодных данных — Open-Meteo.

## Проверки и выпуск

Из корня проекта:

```bash
# Backend и скрипты
cd backend
mvn test
cd ..
node --test backend/scripts/*.test.mjs

# Frontend
cd frontend
npm ci
npm run lint
npm run build
node --test
```

GitHub Actions запускает проверки для pull request и push в `main`. Публикация сайта выполняется отдельно: **Actions → Check and release → Run workflow → main**. Создание GitHub Release само по себе не обновляет сайт.

Production требует отдельных настроек MongoDB с аутентификацией, почты, секретов и согласия на исследование. Базовый локальный Compose не заменяет эту конфигурацию. Инструкции: [выпуск через GitHub Actions](docs/github-releases.md), [аутентификация MongoDB](backend/scripts/README-mongo-auth-migration.md).
