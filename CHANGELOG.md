- У каждого входа теперь отдельная серверная сессия в MongoDB; JWT содержит её идентификатор. Сервер проверяет срок неактивности при каждом защищённом запросе и при обновлении refresh-токена. Просроченную или отозванную сессию нельзя восстановить обновлением токена.

## 2026-05-25 — Фикс race condition при параллельных 401 → auto-refresh

### Баг
Когда страница грузила сразу несколько API-запросов (`attacks`, `medications`, `stats`, `forecast`) и все одновременно получали 401 (истёк access-токен), только **первый** запускал `tryRefresh()` и ставил `isRefreshing = true`. Остальные видели флаг и сразу возвращали `false` → срабатывал `clearSession()` → пользователя выкидывало, хотя refresh-токен был валидный.

### Фикс
`httpClient.tryRefresh()` теперь возвращает **shared promise** вместо булевого флага. Все параллельные 401 дожидаются одной и той же попытки рефреша:
- Первый вызов создаёт `refreshPromise` и шлёт `/auth/refresh`
- Все последующие в эту же миллисекунду получают **ту же promise** и ждут результат
- Когда промис резолвится — все продолжают свои retry с новым токеном
- `refreshPromise = null` в `setTimeout(0)` — чтобы все вызывающие успели прочитать результат до сброса

Теперь юзера выкидывает только если refresh-токен реально протух (30 дней).

## 2026-05-22 — Фикс «не работает кнопка сохранения приступа»

- **Файл:** `src/entities/attack/model/storage.js`
- **Симптом:** при открытии dev-сервера по сетевому IP (например, `http://10.176.120.113:5175` — для теста с телефона) клик по «Сохранить приступ» ничего не делает; в консоли — `TypeError: crypto.randomUUID is not a function`.
- **Причина:** `crypto.randomUUID()` доступен только в secure context (HTTPS или `localhost`/`127.0.0.1`). По обычному HTTP с сетевого IP объект `crypto` существует, но метода `randomUUID` нет → `addAttack` бросает исключение → submit обрывается, модалка не закрывается, приступ не сохраняется.
- **Что сделано:** добавил небольшой fallback-генератор UUID (`generateId`) в `storage.js`, который пробует `crypto.randomUUID`, иначе `crypto.getRandomValues`, иначе `Math.random`. `addAttack` теперь использует его.
- **Что НЕ меняется:** структура объекта приступа, ключ localStorage, API экспортов entity.

  1. Фиксированный `viewBox="0 0 800 240"` и `width:100%` (без явного `width` на SVG) → браузер тянет всё содержимое пропорционально, в т.ч. текст.
  2. Tooltip всегда центрировался по столбику (`translateX(-50%)`), без проверки границ.
- **Что сделано:**
  1. SVG получает реальную пиксельную ширину через `ResizeObserver` на враппере (`min: 280px`). `viewBox` теперь равен реальному размеру → шрифты остаются стабильного пикселя, столбики тянутся, текст — нет.
  2. Позиция tooltip считается в пикселях. Если центр столбика ближе чем половина ширины tooltip к левому/правому краю — переключаем `translateX` на 0 / -100% (липнет к ближайшему краю). По умолчанию остаётся центрирование.
