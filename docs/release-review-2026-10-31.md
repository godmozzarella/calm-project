# Проверка обновления от 31 октября 2026

Проверена рабочая версия изменений регистрации, почтовых кодов, восстановления и смены пароля/почты, админской рассылки, дневника, календаря, гостевой страницы и выгрузки истории. Проверка относится к локальному проекту. Production автоматически не публиковался.

## Исправления

- Вместо сохранения целого устаревшего объекта пользователя профиль, аватары, роли, коды и отметки отправленных уведомлений обновляют только свои поля. Параллельное редактирование профиля больше не возвращает старый пароль или старую почту.
- Атомарная резервация кода выполняется до отправки письма: проигравший конкурентный запрос не отправляет письмо. Проверка и потребление почтового кода выполняются атомарно с проверкой срока, хеша и лимита попыток. Отмена незавершённой регистрации не удаляет уже подтверждённый аккаунт. При отмене дополнительно проверяется отсутствие записей дневника; автоматического удаления старых аккаунтов нет.
- Единая серверная политика паролей для новых регистраций, восстановления и смены: 8 символов, верхний/нижний регистр, цифра; спецсимвол необязателен. Проверяется предел BCrypt — 72 байта UTF-8, включая многобайтовые символы. Старые аккаунты не переводятся в состояние ожидания регистрации.
- Запоздалый ответ старой сессии не может сбросить новую сессию после смены аккаунта. Запрос API обновляет сессию и повторяется максимум один раз; бесконечный цикл refresh/401 исключён.
- Попытка админской рассылки имеет постоянный уникальный ключ в MongoDB. Повтор запроса после обрыва не запускает рассылку заново. Перед каждым письмом перепроверяется подписка. После аварии процесса частичная рассылка автоматически не возобновляется: это сознательная защита от повторных писем, требуется разбор оператором.
- Загрузка аватара проверяет сигнатуру PNG/JPEG/GIF/WebP; SVG и файлы с поддельным MIME отклоняются. Поток загрузки закрывается.
- Карусель восстанавливает переход через край после потери transitionend и сохраняет остаток таймера при паузе. Убран lint warning календаря.
- Обновлены Spring Boot до 3.5.16 и springdoc до 2.8.17; production Swagger отключён. npm lockfile обновлён совместимыми исправлениями, включая DOMPurify и React Router.

Исходные приступы, препараты, заметки и аккаунты остаются в MongoDB на прежнем Docker volume. Прогноз не является условием создания или сохранения приступа. Интеграционный тест записывает приступ за 2020 год без прогноза, меняет пароль, входит заново и читает ту же запись.

Уточнение от 2026-11-01: все разрешённые действующим согласием приступы и препараты сохраняются в существующем `training_examples`, включая записи задним числом без прогноза. Пропуски — `null`. Отдельная таблица истории отменена. Строка содержит все приступы дня, зоны и связанные приёмы; CSV сохраняет полные подробности. `trainingEligible` отмечает пригодность для встроенной офлайн-оценки, но не исключает записи из датасета. Подробный действующий формат — в `training-data-contract.md`.

## Выпуск

Сценарий `.github/scripts/deploy-on-server.sh` собирает образы заранее, останавливает backend/worker, сохраняет основную базу `calm` и аватары в закрытую `.release-backups`, проверяет целостность архивов и контрольные суммы, затем запускает обновление с прежними томами. При ошибке копирования обновление останавливается и старые контейнеры запускаются снова. В этом сценарии нет удаления томов, очистки базы или преобразования старых приступов.

Резервные копии содержат персональные данные: каталог исключён из Git и создаётся с правами владельца. Проверка gzip/tar не заменяет независимую проверку восстановления. При фактическом релизе сохранить копию вне диска VPS по принятой процедуре резервирования. Принятый срок хранения 30 дней распространяется и на `.release-backups`: старые копии необходимо удалять из всех мест хранения по инструкции `backend/scripts/README-mongo-auth-migration.md`. Скрипт не делает автоматический rollback образов после неуспешного запуска новой версии.

## Граница проверки

Полный набор backend-тестов запускается с временной embedded MongoDB; почта в тестах замокана, реальные рассылки не отправляются. Экспорт проверяется unit-тестами и в отдельном Docker-проекте на синтетических данных с MongoDB auth. Frontend проходит ESLint, Node tests и production build.

Сохраняются умеренные advisory в dev-зависимостях ESLint/minimatch: npm не предлагает совместимого исправления. В production npm-зависимостях после обновления обнаруженных advisory нет. Это не утверждение об отсутствии любых уязвимостей. Нативное автозаполнение и визуальное поведение Firefox/Android/iOS требуют ручного прогона на этих браузерах; сборка и тесты не заменяют такую проверку.
