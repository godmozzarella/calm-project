# Проверка совместимости релиза 2026-11-01

Обновление проверяется относительно `origin/main` 2c25214428034a60e71bdfa80d8724fd6bd647b7. Этот SHA соответствует последнему успешному серверному workflow от 26 октября. До нового выпуска публичный health вернул UP; локальные данные не выдаются за состояние production.

## Совместимость

- MongoDB остаётся на прежних volumes и mongo:7. Новые поля пользователя/событий необязательны. Старые подтверждённые и неподтверждённые аккаунты без `registrationPending` сохраняют возможность входа; новый флаг применяется только к новым регистрациям. Пароли существующих пользователей не пересчитываются. Сессии завершаются только при явной смене пароля/почты.
- Восстановление пароля использует согласованные endpoints request/verify/confirm, frontend и backend выпускаются вместе. Новый verify включён и в серверный allowlist, и в список публичных запросов клиента.
- Старые местоположения дополняются только при отсутствии eventLocation. Исходные симптомы, зоны, препараты, даты и прочие поля не переписываются. Режим старого профиля по умолчанию MANUAL; для периодических проверок нужно один раз выбрать автоопределение.
- Названия исходных коллекций и базы датасета не меняются. Сборщик читает всю разрешённую действующим согласием историю, включая старые приступы без прогноза. HMAC-ключи и настройки участия на сервере сохраняются. Ретроспективная погода помечается отдельно; исходные прогнозы не переписываются.
- В production nginx отдельно перенесены запрет кеширования HTML, кеширование хешированных assets и лимит загрузки 6 МБ. Публичный URL для ссылок смены почты явно задан в production Compose.
- Папка public со скринами, мокапом, шрифтами и иконками должна входить в коммит: локального наличия файлов недостаточно для серверной сборки. CSV и резервные копии пользователей не входят в релиз.

## Релиз и восстановление

До остановки сервисов сохраняются ID старых образов и собираются новые. После остановки backend/worker создаются закрытые архивы MongoDB и аватаров с проверкой gzip/tar/SHA-256. Перед и после additive-переноса сравниваются количества и SHA-256 исходных полей пользователей, приступов, приёмов и личного справочника (новое eventLocation исключено из хеша). Несовпадение прерывает запуск.

При ошибке после остановки выполняется попытка запуска прежних backend/frontend через сохранённый override, volumes не удаляются. Рабочий Git checkout и новые файлы worker при этом не откатываются. История MongoDB автоматически не восстанавливается из архива: для additive-миграции это не требуется. Архив нужен на случай отдельного восстановления оператором; его хранение и удаление выполняются по существующей политике резервирования.

Проверки сценария релиза моделируют нормальную выкладку, испорченный backup, несовпадение данных и неуспешный запуск новой версии. Изолированная MongoDB с auth отдельно проверяет реальные dump/restore, идемпотентность миграции, неизменность исходных хешей, полноту истории и отзыв согласия.

## Проверки до публикации

- 84 backend-теста; frontend ESLint, 17 Node-тестов и production build.
- 36 тестов скриптов, включая 4 сценария релиза.
- Production nginx: nginx -t успешно.
- Изолированная MongoDB с auth: backup/restore, хеши исходных полей, перенос мест и v3-экспорт успешно.
- Браузерные проверки текущей локальной сборки ранее подтвердили последовательные шаги восстановления, обычное начертание восьми текстов футера, переключение темы, мобильные памятки установки и корректные PNG/manifest. Нативные установка iOS/Android и GPS не проверялись на реальных устройствах.

Статус публикации и фактический результат production следует сверять с новым Actions run; успешные локальные проверки сами по себе не означают выложенный релиз.
