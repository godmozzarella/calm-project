# Местоположение событий и архивная погода — 2026-11-01

## Режим выбора города

`User.locationMode` — `MANUAL` либо `AUTO`. Старые профили без этого поля считаются ручными: прежний способ выбора города в базе не сохранялся, достоверно восстановить его нельзя. Для включения периодических проверок нужно один раз снова нажать «Определить автоматически».

- Ручной город закреплён до явного выбора пользователем другого города или авторежима. Фоновое предложение обновления не может изменить ручной профиль даже при устаревшем интерфейсе другой вкладки: сервер проверяет режим и `locationVersion` атомарно.
- В авторежиме приложение проверяет координаты при входе/возврате во вкладку и периодически в видимой вкладке, не чаще одного раза в 6 часов на вкладку. Смена названия города либо перемещение на 20 км внутри одного города вызывает вопрос «Вы находитесь здесь?». Только «Да» сохраняет новые координаты; «Нет», Escape, отказ геолокации и ошибка сети оставляют прежний город.
- Геолокация требует разрешения браузера и защищённого контекста (HTTPS либо localhost). Приложение не отслеживает пользователя, когда оно закрыто.

## Фиксация места

Подтверждённые изменения сохраняются в закрытой истории профиля вместе со временем, режимом и часовым поясом. Приступ и приём препарата получают неизменяемый `eventLocation`: координаты, город, часовой пояс, способ выбора, происхождение и время фиксации. Редактирование симптомов, зон, дозировки или интенсивности сохраняет прежнее место. При изменении даты/времени события место определяется заново.

Для новой записи в ручном режиме используется текущий явно заданный город, в том числе для старых дат. В авторежиме для старой даты используется доступная история подтверждённых мест; для дат до первой известной точки берётся первая выбранная точка с пометкой допущения. Эти точки фиксируют подтверждённое настройками место, а не непрерывный маршрут пользователя.

При первом выборе города незаполненные места уже существующих записей фиксируются по первой известной точке. Миграция релиза заполняет только отсутствующий `eventLocation` по текущему сохранённому профилю (`LEGACY_PROFILE_ASSUMPTION`). Она не заменяет уже сохранённое место и не удаляет записи. Если места в профиле нет, координаты не выдумываются.

## Архивная погода в том же датасете

Экспортёр по-прежнему публикует всю разрешённую историю в `training_examples`. Точные координаты и названия городов в общий набор не передаются: для погоды используется округлённая сетка 0,1°. У каждого приступа и приёма есть своя `location` и `historicalWeather`. Переезд не меняет архивную погоду старого события. Для дня с разными местами выставляется `weatherLocationsMixed`; погода разных городов не склеивается в один неподтверждённый показатель.

Архив Open-Meteo запрашивается по месяцам и месту за дату события и предыдущие сутки. Сохраняются среднее поверхностное давление в мм рт. ст., его суточный перепад, средняя влажность и её перепад, минимум/максимум температуры и максимальные порывы ветра в км/ч. Источник — `OPEN_METEO_ARCHIVE`, тип — `RETROSPECTIVE_BEST_MATCH`, сохранены время получения и часовой пояс API. Это ретроспективные данные, а не прогноз, существовавший до события. Kp и балл персонального риска из погодного архива не выдумываются.

Архив заполняет только отсутствующие погодные параметры в `features`; исходные снимки не изменяются. `weatherFeatureSources` отличает `SAVED_SNAPSHOT` и `HISTORICAL_ARCHIVE`. Строки с ретроспективно дополненными признаками остаются в датасете, но не используются встроенной проверкой предварительного прогноза. Пользовательская предобработка может брать весь набор.

Прежние выгрузки используются как кеш. По умолчанию за цикл выполняется до 12 месячных запросов с ограничением времени; следующие циклы продолжают заполнение. Ошибки API не исключают приступы из набора: недоступные поля остаются `null`. В `export_metadata` есть число запросов, ошибок и оставшихся групп. Управление: `CALM_HISTORICAL_WEATHER_ENABLED=false` отключает только сетевое дополнение; `CALM_HISTORICAL_WEATHER_BATCH_SIZE` регулирует пакет (1–100, общий временной бюджет сохраняется).

Документация поставщика: https://open-meteo.com/en/docs/historical-weather-api

## Выпуск

После проверенной резервной копии и остановки писателей сценарий релиза запускает `backfill-event-locations.js` с URI приложения, имеющим право записи. URI не выводится в журнал. Исходная учётная запись worker остаётся read-only. Повторная миграция не заменяет уже зафиксированные места. После запуска backend выполняется одноразовая полная выгрузка всех старых приступов и препаратов; затем запускается обычный worker. При недоступном погодном API сами записи всё равно публикуются с пропусками, а заполнение продолжается в следующих циклах.

Изменения не публиковались на production автоматически. Проверки: backend-тесты строгого ручного режима, подтверждённых/устаревших обновлений, истории и неизменности старых событий; frontend-тесты политики предложений; тесты агрегации/единиц/пропусков архива; реальный тест публичных координат Open-Meteo; изолированный MongoDB dump/restore и идемпотентная миграция.

## Результаты проверки

- Backend: 82 теста, 0 ошибок, включая HTTP-проверку ручного режима, устаревшего автоматического подтверждения и неизменности места старой записи; проверено место у приступа и препарата и заполнение после первого выбора города.
- Frontend: ESLint без замечаний, 16 Node-тестов, production build успешен. Проверены отсутствие автоматических предложений в ручном режиме и подавление небольшого GPS-сдвига в том же городе.
- Скрипты: 32 теста; проверены давление/перепады/нулевые и пропущенные значения, повторное использование архива, сохранность места при переезде, запрет выдавать ретроспективные значения за своевременные.
- Изолированная MongoDB с аутентификацией: настоящие ObjectId пользователей, миграция дважды (повторно без изменений), backup/restore, загрузка погодного модуля в mongosh, публикация и удаление производных строк после отзыва согласия.
- Реальный архивный запрос для публичных тестовых координат Берлина за 2020-01-02 завершился успешно.
- Локальные Docker-образы пересобраны и запущены; frontend отвечает HTTP 200, health backend — `UP`. Перед миграцией сохранены база и аватары с контрольными суммами. Добавлено место к 43 приступам и 29 приёмам; повторный запуск изменил 0 записей. Сверка хешей всех исходных полей (без нового `eventLocation`) до/после подтвердила сохранность данных.

Нативный GPS и диалог разрешения браузера не проверялись на реальном телефоне. Фон проверен сборкой; отдельного визуального прогона браузера в этой сессии не было.
