# Продолжение подготовки пилота общей модели

Обновлено: 2026-10-12

## Цель

Подготовить Calm к безопасному ограниченному пилоту общей модели прогноза головной боли. Результат остаётся экспериментальным и офлайн, пока не появятся реальные данные и проверка качества. Не называть текущую оценку вероятностью.

## Уже подготовлено

- Сбор исхода дня различает `ATTACK_STARTED`, подтверждённое `NO_ATTACK_STARTED` и неизвестный `UNKNOWN`; неизвестные дни не попадают в обучающую выборку.
- После обновления рабочих backend и frontend 2026-10-12 будущие прогнозы сохраняются со снимком признаков версии `2`, версией правил `personal-rules-v1` и временем/часовым поясом. Старые снимки версии `1` остаются в базе, но в новую офлайн-выгрузку не входят.
- Проверка подтверждения отрицательного исхода использует часовой пояс сохранённого прогноза, чтобы не подтвердить день до его завершения в месте прогноза. Два теста сервиса прошли.
- Добровольное участие требует совпадения версии и SHA-256 отпечатка текста; согласие можно отозвать. На 2026-10-12 локальный enrollment открыт по просьбе пользователя; worker подключён с отдельными Mongo-ролями и работает каждые 5 минут. Текст черновой, внешний набор закрыт. Первый снимок пуст: активных согласий 0, подходящих примеров 0.
- Рабочий локальный Mongo переведён на `--auth`; backend подключается под `calm_app`, worker читает исходную базу как `calm_risk_export_reader` и пишет в `calm_risk_training` как `calm_risk_training_writer`. Роли, URI и HMAC-ключ лежат в игнорируемых файлах с режимом `600`. Контейнеры здоровы, API отвечает `UP`. Сайт доступен по `http://192.168.31.71/` в текущей Wi-Fi/LAN сети; frontend привязан к этому IP и localhost, backend/Mongo — только к localhost, worker не публикует порт.
- Пользователь зарегистрировал домен `peaceofmindforyourhead.duckdns.org`; после покупки VPS направить его на публичный IPv4 сервера и использовать для HTTPS и ссылок подтверждения email.
- VPS куплен и подготовлен: Ubuntu 24.04.4, Docker/Compose установлены, системные обновления применены, UFW разрешает 22/80/443; DNS домена уже указывает на `193.23.195.216`. Production Compose с Caddy/HTTPS подготовлен и проверен локально, но ещё не загружен на сервер и не запущен.

Рабочие изменения документов и сгенерированный `backend/target` не закоммичены. Перед клонированием/обновлением сервера проверить push в develop и выбрать только нужные файлы для коммита.

- Блок исхода дня в интерфейсе исправлен; `npm run build` прошёл. Таргетированные backend-тесты часового пояса прошли (2/2). Рабочая база не менялась.

## Что блокирует пилот

1. Локальная MongoDB теперь защищена авторизацией и не доступна извне хоста. UFW на VPS включён; проверить внешний firewall провайдера, SSH-ключи и production MongoDB после запуска.
2. Свежая копия в `~/CalmBackups/2026-10-12T195259+0300` прошла восстановление. Пользователь выбрал хранить серверные копии на собственном Mac без шифрования на диске. Настроить получение и проверить восстановление копии VPS; учитывать риск потери/недоступности Mac.
3. Пользователь утвердил действующий текст согласия `shared-model-pilot-v1` 2026-10-12. Внешнее открытие набора отложено до подготовки сервера и проверки HTTPS, секретов и резервного копирования. Worker строит псевдонимизированный снимок, но не обучает и не активирует модель автоматически.
4. Синтетическая фикстура годится только для smoke-check конвейера, а не для выводов о точности общей модели.

## Следующие действия

1. VPS и DNS готовы. Передать проверенный develop на сервер. Сначала перенести текущую базу двух пользователей и аватары через проверенную копию; не начинать с пустой базы. MongoDB держать только в Docker-сети без опубликованного порта.
2. Запустить `docker-compose.prod.yml`: Caddy обслуживает `peaceofmindforyourhead.duckdns.org`, получает HTTPS Let's Encrypt и перенаправляет HTTP на HTTPS. Только Caddy публикует 80/443; backend, frontend и MongoDB портов на хост не публикуют. Проверить сертификат снаружи и его автообновление.
3. На сервере создать новые уникальные секреты; локальные значения не копировать. Хранить env-файлы с правами `600`, исключённые из Git. Для Gmail SMTP владелец аккаунта должен отозвать прежний App Password и создать новый; пароль вводить через скрытый скрипт, не отправлять в чат.
4. Настроить копирование MongoDB и аватаров на Mac по SSH. Пользователь принимает хранение там без отдельного облака; проверить расписание и восстановление. Если Mac выключен или недоступен, копирование пропустится.
5. Текущая версия согласия утверждена пользователем; включить внешний enrollment после серверных проверок. Затем сверить экспорт агрегатно. Не трактовать технический offline-кандидат или синтетические метрики как медицинскую/прогностическую валидность.
